# 今天这顿

每天三个饭点自动打开，只推荐一道菜，点一下跳到外卖 App 下单。

设计文档：`docs/superpowers/specs/2026-08-22-meal-recommender-design.md`

## 它不做什么

- 不代替你下单或支付 —— 只给推荐和跳转链接，最后一步你自己完成
- 不抓取任何外卖平台数据 —— 候选池由你手动录入
- 没有服务器 —— 数据只存在你这台手机的浏览器里

## 为什么是这个形状

这个 app 没有账号、没有后端、没有推送服务器，只有三条你自己设的 iOS 快捷指令
和一份存在浏览器本地的候选池。这不是偷懒，是有意为之：一顿饭的推荐值不上一整套
账号体系和云端存储。代价是几处需要你自己维护的地方 —— 手动录入候选池、手动配置
快捷指令、手动记得导出备份 —— README 把这些都写清楚了，因为它们不会在界面上
提醒你。

## 首次使用

### 1. 部署

这是一个纯静态站点，零构建步骤，直接推到 GitHub Pages 即可：

1. 把仓库推到 GitHub，例如 `xiaoyu-studio/meal`
2. 打开**仓库自己的** Pages 设置页 `https://github.com/xiaoyu-studio/meal/settings/pages`，
   把 Branch 设为 `main` / `(root)`。注意别进成账号设置里的 Pages 页 ——
   那一页只有「Verified domains」，管的是自定义域名，改不了发布分支
3. 几分钟后访问 `https://xiaoyu-studio.github.io/meal/`

### 2. 添加到主屏幕（必做）

用 **Safari** 打开上面的地址 → 分享按钮 → 「添加到主屏幕」。

这一步不是为了好看：Safari 的智能防跟踪（ITP）会在网站 7 天无访问后清理它的
脚本可写存储（包括 IndexedDB），**但已安装到主屏的网页豁免这条规则**。
不装到主屏，你的候选池和几个月攒下的用餐历史迟早会被 Safari 静默清空，
而且不会有任何提示。

### 3. 录入候选池

点页面底部「候选池」。每家店需要：

1. 在美团或饿了么 App 里找到这家店
2. 点「分享」→ 复制链接
3. 回到候选池，填店名、选平台、粘贴链接
4. 在该店卡片下方逐道添加菜品

先录 5 家就能开始用，20–30 家会明显更好用。

### 4. 配置三条快捷指令

**地址必须用 `webapp://` 开头，不能用 `https://`。** 这是这一步唯一容易出错、
而且错了不会报错的地方，先说清楚为什么：

iOS 把「Safari」和「装到主屏的网页」当成两个独立的存储容器。用 `https://`
打开时，系统会把它开在 Safari 里，而 Safari 那份 IndexedDB 是空的 ——
你会看到一个**没有任何店铺和菜品的空候选池**，像是数据丢了。数据没丢，
只是开错了门。更要紧的是，第 2 步说的那个 ITP 豁免**只对主屏那个窗口有效**,
开在 Safari 里的话，7 天不用照样会被清空。

`webapp://` 才会唤起你装在主屏上的那个。

打开 iOS「快捷指令」App → 底部「自动化」→ 右上角 `+` → 「特定时间」。

建三条，时间分别对应三个饭点：

| 时间 | 地址（三条都填同一个） |
|---|---|
| 08:00 | `webapp://xiaoyu-studio.github.io/meal/` |
| 11:30 | 同上 |
| 17:30 | 同上 |

时间按自己作息调整。地址里的域名换成你自己的 Pages 地址，**去掉 `https://`**。

三条地址完全一样不是笔误：`webapp://` 会把 query 参数丢掉，直接开到
manifest 里的 `start_url`。所以 `?slot=lunch` 这类参数写了也没用 ——
但不影响，页面本来就会按当前时间推断是哪一顿（见 `src/dates.js` 的
`slotFromTime`），上面三个时间点推出来的结果都是对的。

**每条自动化里要设的两处：**

- 设完时间往下，选「**立即运行**」而不是「确认后运行」。
  （iOS 17 之前这里叫「运行前询问」，现在拆成了这一对选项，而且就在设时间那一页，
  不在最后的汇总页）
- 选完「立即运行」后下面会冒出「**运行时通知我**」，想安静就关掉

**动作选「打开 URL」。** 如果在操作搜索框里搜 `URL` 搜不到（iOS 26 上会这样），
改搜 `Safari`，在它名下的操作列表里找。

**已知限制：** 到点后屏幕会亮，但**需要你解锁之后才会真的进到页面**。
这是 iOS 的安全限制，不是配置问题。

## 日常使用

到饭点手机会亮屏，解锁后进推荐页。点「去下单」跳到外卖 App 完成支付。

想看看别的就左右滑动卡片，或者点右上角「下一个」—— **没有次数上限，
而且左右都是循环**，划过头了往回划就能找回来。**浏览不算表态**：
划过的菜不会被记成「不想吃」，也不影响它以后的排序。

某道菜确实不想再看到，点「别再推这个」—— 它会被大幅降权，之后随时间慢慢回来。
这是降权不是拉黑；要彻底排除某家店，去候选池把它的卫生标记改成「已拉黑」。

下一顿打开时会补问上一顿怎么样 —— 一次点击就好。点过「去下单」的那顿，
要等下单满 2 小时才会问，免得外卖还没到就问你好不好吃。

## 备份

候选池页面顶部有「导出备份」，会下载一个 JSON 文件，存进「文件」App 即可。
**建议每月导出一次。** 数据只在这一台手机上，没有别的副本。

页面只会说「已生成 …，请在「文件」App 里确认」，不会说「已导出」—— 浏览器有没有
真的落盘，网页这边看不到。请每次都去「文件」App 里确认那个文件真的在。

## 图标

主屏图标由 `tools/make-icons.mjs` 从 `icon.svg` 的同一套形状生成
（`apple-touch-icon.png` / `icon-192.png` / `icon-512.png`）。改了 `icon.svg`
之后重新跑一次即可：

```bash
node tools/make-icons.mjs
```

脚本只用 Node 自带的 zlib 手写 PNG，是一次性资源生成，不引入任何运行时依赖。
位图是必须的：iOS 不认 SVG 的 `apple-touch-icon`，取不到位图时会拿页面截图
当主屏图标。

## 本地开发

ES Modules 无法从 `file://` 加载，必须走 HTTP：

```bash
python -m http.server 8000
```

然后打开 `http://localhost:8000/index.html`。

## 测试

纯逻辑模块（`config` / `dates` / `observations` / `recommender` / `snapshot`）
零依赖，用 Node 自带的测试运行器：

```bash
node --test
```

`store.js` 与 `ui-*.js` 碰浏览器 API，不在自动化测试范围内，由真机验收清单
`docs/acceptance-checklist.md` 覆盖。

## 调推荐手感

所有可调常数都在 `src/config.js` 里，改完刷新页面即生效。
最可能需要调的是 `FATIGUE_TAU_DISH`（多久不腻，默认 7 天）和
`W_TASTE` / `W_VALUE`（好吃与便宜的权重，默认 0.7 / 0.3）。

## 1. 起因与目标

首页那张卡片一直是「白底、灰字、一个橙按钮」。信息没错，但看着像一张表单。
用户的原话是「太丑了，希望可以活泼一些」，以及「左右滑动的时候卡片跟随手指移动」。

经过四轮样式比稿（scratchpad，不入库），定下的方向是**便签纸**：一张微微歪着、
用胶带贴在彩色底板上的纸，右上角钉一张拍立得，边上散着贴纸。配色跟着饭点换，
深浅色跟随系统。滑动时卡片跟着手指走，松手决定翻页还是弹回。

**这次只改「今天这顿」这一页的外观与手势。** 推荐算法、事件写入、归约逻辑、
补问浮层的行为一律不动。候选池页面 `pool.html` 这次不跟着改（见 §10）。

## 2. 不动的东西

改外观最容易顺手改坏的是下面这些，先钉住：

- **卡片上的信息项一个不增不减**：饭点、菜名、店名、价格、理由、轮播位置、
  「去下单」「复制店名」「别再推这个」「上一个」「下一个」。验收清单里的条目
  都建立在这些元素存在的前提上。
- **`#order` 必须仍是真实的 `<a href>`**。iOS 的 Universal Links 唤不起脚本
  发起的跳转（`deeplink.js` 里有原委）。不能为了按钮样式换成 `<button>`。
- **元素 id 不改**：`slot-label` `dish-name` `shop-name` `price` `reason`
  `carousel-pos` `order` `copy-shop` `mute` `prev` `swap` `card` `empty`
  `failure` `feedback`。`ui-today.js` 里的读写、失败态、静音失败时借用
  `#reason` 显示「没记上」的那段，全都按 id 找元素。
- **`showAt()` 写进 DOM 的仍是 `textContent`**。菜名和店名是用户数据。
- **纯函数边界不动**：新增的取 emoji 逻辑是纯函数，放进纯模块清单一起受约束。
- **不注册 Service Worker，不加任何运行时依赖。** 手绘感全部用 CSS 和内联 SVG
  做，字体只用系统自带的。

## 3. 卡片结构

自上而下（括号是现有 id）：

```
 底板 .board（颜色按饭点）
   └ 舞台 .stage
       ├ 叠影 .peek ×2         后面还有几张的暗示，纯装饰
       └ 纸 .paper             ← 跟手拖动的就是这一层
           └ .sheet            ← 飘动动画在这一层
               ├ 胶带 .tape
               ├ 拍立得 .polaroid   大 emoji + 一行「今晚吃这个？」
               ├ 贴纸 .stickers     ✨ 🔥 ⭐️，pointer-events: none
               ├ 饭点标签           (#slot-label)
               ├ 菜名               (#dish-name)
               ├ 店名 + 价格 一行   (#shop-name) (#price)
               ├ 理由               (#reason)
               ├ 去下单             (#order)
               ├ 复制店名 / 别再推这个
               ├ 底行：← 上一个 · 划一划换一个 · 下一个 →
               └ 轮播位置           (#carousel-pos)
```

拖动层（`.paper`）与飘动层（`.sheet`）**必须分开**。两个 transform 写在同一个
元素上会互相覆盖：拖动时 JS 写 `style.transform`，会把 CSS 动画的 transform
整个顶掉，松手后又要还回去。分两层之后，JS 只碰外层，动画只碰内层，互不相扰。

「上一个 / 下一个」不再是右上角的两个描边按钮，改成卡片最下面一行的两个角标：
没有边框和背景，字号 0.76rem，颜色用最淡的一档。中间是「划一划换一个」。
两个箭头各自朝自己那边轻轻来回推（左的往左、右的往右，错开 0.75 秒）。

### 3.1 轮播位置：横杠还是数字

`.carousel-pos` 原来是「2 / 4」这样一行文字，当初特意没做圆点，理由写在
`style.css` 的注释里：候选可能有几十道，圆点会排到屏幕外。

这个理由仍然成立，所以新的横杠指示**有上限**：

- 候选总数 ≤ 8：画出对应数量的小横杠，当前那道更长、歪 3 度。
- 候选总数 > 8：退回原来的「7 / 23」文字，不画横杠。

8 这个数是量出来的：卡片内容宽度在 375px 屏上是 273px，每杠 16px、间距
7.2px，八杠合计 约 185px，两侧还各留 44px。九杠开始逼近边缘。

### 3.2 拍立得里的 emoji

新增纯模块 `src/emoji.js`：

```js
export function dishEmoji(name) // → 一个 emoji 字符串
```

按关键字匹配菜名，**命中第一个就返回**，一个都不中就返回 `'🍽️'`。
宁可退回通用图标，也不要乱猜 —— 猜错比没猜更扎眼。

关键字表放 `src/config.js`（可调常数只放那里），形如：

```js
export const DISH_EMOJI = [
  [['汉堡', '堡'], '🍔'],
  [['面', '拉面', '米线', '粉'], '🍜'],
  [['饭', '盖浇', '煲仔'], '🍚'],
  [['鸡'], '🍗'], [['披萨', '比萨'], '🍕'], [['粥'], '🥣'],
  [['包', '饺', '馄饨'], '🥟'], [['寿司', '刺身'], '🍣'],
  [['沙拉'], '🥗'], [['火锅', '麻辣烫', '香锅'], '🍲'],
  [['烧烤', '烤'], '🍢'], [['奶茶', '咖啡'], '🥤'],
];
```

顺序即优先级：「鸡汤面」应该出面而不是鸡，所以面排在鸡前面。这一条写进
`emoji.js` 的注释，改表的人得知道顺序是有意义的。

`dishEmoji` 不碰时钟、随机、DOM、存储，列进 CLAUDE.md 的纯模块清单，
并写单元测试（命中、优先级、全不中退回、空字符串、极长菜名）。

## 4. 配色

三个饭点各一套，深浅色各一套，共六组。**颜色写在 CSS 里，不进 `config.js`** ——
`config.js` 装的是参与计算的可调常数（权重、半衰期、阈值），颜色是样式，
放进去反而要多一条「JS 把颜色注入 CSS 变量」的链路，没有好处。

做法是给 `<body>`（或 `#card`）加 `data-slot="breakfast|lunch|dinner"`，
CSS 按属性选择器切换变量：

```css
:root { /* 纸、墨、格子线、标签、按钮的浅色值 */ }
@media (prefers-color-scheme: dark) { :root { /* 深色值 */ } }

[data-slot="breakfast"] { --board-a: …; --board-b: …; --chip-bg: …; --chip-fg: …; }
[data-slot="lunch"]     { … }
[data-slot="dinner"]    { … }
@media (prefers-color-scheme: dark) {
  [data-slot="breakfast"] { … }   /* 深色下三套底板都压暗 */
  …
}
```

大致取值（比稿里验过的）：

| | 底板（浅） | 底板（深） | 标签底/字（浅） |
|---|---|---|---|
| 早餐 | `#f6c85f` → `#e8a33d` | `#3a2a12` → `#1a1408` | `#ffe6a8` / `#8a5a12` |
| 午餐 | `#f08a4b` → `#c9552e` | `#3a2014` → `#1a0e08` | `#ffdcc2` / `#8a3a12` |
| 晚餐 | `#3b2a52` → `#2a1f3d` | `#241a33` → `#14101d` | `#e6dcff` / `#4a2d7a` |

纸本身浅色是 `#fffdf7`，深色是 `#26201b`（深棕木色，不是纯黑 —— 便签纸的
质感靠这个撑着）。深色下胶带和拍立得相框要压暗（`rgba(206,170,96,.55)`、
`#e4dbcd`），否则夜里一张纯白拍立得会在屏幕上发光。

`data-slot` 由 `render()` 在算出 slot 之后写一次，跟 `#slot-label` 同一处。
从后台切回来跨了饭点时 `refreshIfStale()` 会重画，属性跟着更新。

## 5. 字体

菜名和拍立得说明用：

```css
font-family: "Yuanti SC", "PingFang SC", -apple-system, sans-serif;
```

`Yuanti SC`（圆体-简）是 iOS/macOS 自带的，圆头圆脑，是「活泼」里最省力的一笔。
Windows 和 Android 上没有，会退回苹方/系统字体，**桌面浏览器上看不出差别，
只有真机能验** —— 写进验收项。

## 6. 动效

| 对象 | 动作 | 参数 |
|---|---|---|
| 纸 `.sheet` | 上下飘 | 5s 一个来回，位移 5px，同时 -1.6°↔-0.5° |
| 拍立得 | 左右摇 | 4.2s，7°↔11.5°，转轴在上边中点（像钉住了） |
| ✨ | 一闪一闪 | 2.4s，透明度 .35↔1，缩放 .85↔1.12 |
| 🔥 | 打摆 | 1.8s，±7° |
| 贴纸 | 换卡时弹出 | 0.42s，`cubic-bezier(.2,1.5,.5,1)`，三张错开 0.08s |
| 卡片 | 入场 | 从侧面 120% 处飞入，0.38s，带过冲 |
| 卡片 | 出场 | 往反方向 130% 飞出并淡出，0.2s |
| 两个箭头 | 各自推 | 1.5s，±3px，左右错开 0.75s |
| 「去下单」 | 按下 | 下沉 5px、厚边从 6px 压到 1px，0.08s；同时纸的投影收紧 |

**`prefers-reduced-motion: reduce` 时全部关掉**（飘、摇、闪、打摆、弹、入场、
出场、箭头），只留下：按钮按下的位移（这是操作反馈，不是装饰）和**跟手拖动**。
跟手不能关 —— 关掉手势就等于关掉一个功能，那不是「减少动效」的意思。
换卡时直接切内容，不放飞出/飞入。

项目已有 `@media (prefers-reduced-motion: reduce)` 段落（`.toast` / `.shop-block`），
新的选择器加进同一段，不另起。

## 7. 跟手滑动

### 7.1 现状

现在是 `touchstart` 记起点、`touchend` 比位移，中间什么都不画：手指划的时候
卡片一动不动，松手瞬间内容直接换掉。两个监听器都挂在 `#card` 上，都是
`{ passive: true }`，位移阈值 `SWIPE_MIN_X = 50`，且要求 `|dx| > |dy|`。

验收第 17 条验的就是「滑动不与纵向滚动打架」—— 这条行为必须原样保住。

### 7.2 改成什么

换成 Pointer Events（一套代码同时管触摸和桌面鼠标，桌面上也能拖，省得手势
只能靠真机验）。挂在 `.paper` 上。

```
pointerdown  → 记起点，锁 pointer capture，暂停飘动动画
pointermove  → 第一次移动先定轴向，之后只在横向轴上跟手
pointerup    → 过阈值就翻页，不过就弹回
pointercancel→ 按「没滑」处理，弹回
```

**轴向锁定**（保住验收第 17 条的关键）：

- 起点之后，位移在任一方向上还不到 6px 时，什么都不做 —— 手指刚落下时的
  抖动不该决定方向。
- 第一次超过 6px 时，比较 `|dx|` 和 `|dy|` 定下轴向，**这一次之后不再改**。
- 判为纵向：立刻放手（当作没滑），页面正常滚动。
- 判为横向：开始跟手。

`.paper` 上写 `touch-action: pan-y`。这一句是分工的关键：浏览器仍然负责纵向
滚动，横向的手势交给 JS —— 于是**不需要 `preventDefault`，监听器可以保持
`passive`**。比「把监听器改成非 passive 再手动 preventDefault」干净得多，
也不会有「滚动一卡一卡」的副作用。

**跟手位移带阻尼**：

```js
const damped = Math.sign(dx) * Math.pow(Math.abs(dx), 0.88);
paper.style.transform = `translateX(${damped}px) rotate(${damped / 26}deg)`;
```

0.88 次幂的意思是：小位移几乎一比一跟手（拖 20px 走 14px），拖得越远越沉
（拖 160px 走 92px）。同时按位移的 1/26 做轻微旋转 —— 纸被推着走的时候
会偏一点，正着平移反而假。

**阈值与结果**：

- `|dx| > 卡片宽度 × 0.32` → 翻页。往左翻下一道，往右翻上一道，跟现在一致。
  用比例不用固定像素：换个更宽的屏，手感才一样。（375px 上约等于 109px，
  比现在的 50px 严，但现在那 50px 是「松手才判定」的阈值，跟手之后用户对
  位移有实感，阈值可以更大也不会误判。）
- 不到阈值 → 弹回原位，0.3s，`cubic-bezier(.2,1.4,.4,1)` 带一点过冲。
- 翻页动画：当前卡片继续往那个方向飞出去（0.2s，淡出），换内容，新卡片从
  反方向飞进来（0.38s，带过冲）。

**翻页仍然只调 `step(±1)`，不写任何事件** —— 浏览是免费的，这条不变。

### 7.3 几个容易踩的坑

- **按钮上起手不能拖卡片。** `pointerdown` 里先 `e.target.closest('a, button')`，
  命中就直接不管 —— 否则在「去下单」上手指稍微一滑，链接点不动了。
- **`setPointerCapture` 要包 try/catch。** 合成事件或奇怪的 pointerId 会抛。
- **飞出动画结束后必须清掉 `style.transform`**，否则下一张卡片会带着上一张的
  位移出场。
- **静音失败时借用 `#reason` 显示「没记上」的那段逻辑**依赖「2 秒内用户可能
  翻页」，现在翻页多了动画，那 2 秒里卡片可能正在飞 —— 判据是
  `state.dish?.id === dish.id`，跟动画无关，不受影响，但改的时候别顺手删了。

## 10. 明知道的取舍

- **候选池页面不跟着改。** 首页变便签风之后，点进候选池会看到原来那套白底
  列表，两页风格不一致。接受这个不一致，理由是：候选池是「管理数据」的页面，
  每周开不了一次，把它也做成便签墙既费工又会让长列表更难扫。等首页真机用
  一阵子之后再决定要不要跟进。
- **横杠指示有上限**（§3.1）。超过 8 道菜就退回数字，这是个断崖式切换，
  不做渐变（比如缩短横杠）—— 缩到 6px 的横杠既看不清也点不着，不如直接给数字。
- **`Yuanti SC` 只在苹果设备上生效**（§5）。不为此打包字体：一个中文字体子集
  至少几百 KB，违反零依赖的初衷，也拖慢首屏。
- **拍立得的 emoji 会猜错。** 关键字表就那么十几行，「佛跳墙」「麻辣拌」之类
  一律落到 🍽️。宁可不猜。
- **跟手用 Pointer Events，iOS Safari 15 以下不支持。** 项目本来就只跑在
  用户自己的 iPhone 上（iOS 17+），不做降级。

## 11. 怎么验

新增五条真机验收项（写进 `docs/acceptance-checklist.md`，编号 27–31）：

27. **便签卡片在 375px 下不破版**：长菜名（用候选池里那家长名字测试店）不被
    拍立得压住、不溢出纸面；底行三样不换行；横杠居中。
28. **三个饭点各一套配色**：用 `?slot=breakfast` / `lunch` / `dinner` 逐个打开，
    底板、标签、拍立得说明（「早上/中午/今晚吃这个？」）三处都跟着变。
29. **跟手**：手指按住卡片横向拖，卡片实时跟着走并轻微倾斜；拖不到三分之一
    松手弹回原位、菜不变；拖过三分之一松手，卡片飞出、换下一道、横杠跟着走。
    **在卡片上纵向滑动，页面正常滚动，卡片不跟着横移。**（这条就是第 17 条的
    重验，两条一起做。）
